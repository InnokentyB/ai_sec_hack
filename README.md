## MVP

Одна глубина: владелец → оркестратор → исполнитель. Одно действие:
доставка конкретного synthetic документа конкретному получателю в локальный inbox.
Права сужаются, исходный лимит общий для всех детей. Подмена, отзыв, expiry и replay
проверяются перед dispatch. Неизвестный результат не выдаётся за успех.
Журнал и экспорт подписаны; verifier получает доверенные fingerprints отдельно.

Никаких реальных подписей договоров, платежей, внешних отправок или live provider в MVP.
Блокчейн — необязательное будущее закрепление контрольных хешей, не реализован.

## Разработка

Все installs/builds/tests/browser automation на Tower только внутри Docker.
Dockerfile и Compose находятся в `docker/`. Команды выполняются из корня проекта на Tower.
Compose создаёт отдельную сеть и автоматически выбирает подсеть; `.env` необязателен.
На текущем Tower пул стандартных подсетей исчерпан (сообщение параллельной проверки).
Поэтому успешная валидация Compose не означает успешный `up` на этом хосте:
для запуска потребуется отдельно выбрать свободную подсеть через Compose override.
Существующие сети и работающие сервисы не удалять.
Продуктовые секреты, ключи, базы и runtime artifacts не коммитить.

TDPD / Test-Driven Product Development — оригинальный метод Иннокентия Бодрова.
Лицензия пока не выбрана. Конкурсная подача и юридическая значимость не заявляются.


## Запуск прототипа на Tower

```sh
docker compose -f docker/docker-compose.yml build tests
docker compose -f docker/docker-compose.yml run --rm tests pytest -q -p no:cacheprovider tests/integration
docker compose -f docker/docker-compose.yml up -d app receiver
docker compose -f docker/docker-compose.yml ps
docker compose -f docker/docker-compose.yml logs --tail=80 app receiver
docker compose -f docker/docker-compose.yml stop app receiver
```

Порт по умолчанию: `127.0.0.1:8080`. Параметры перечислены в `.env.example`.
При SSH-пробросе на другой порт задайте `LEDGER_ORIGIN` равным адресу в браузере.
Ключи доступа создаются в `/data/credentials.json`; не выводите их в общие логи.
Один app worker; receiver хранит отдельную базу и ключ. Незавершённые попытки после
перезапуска остаются uncertain, слот не освобождается и отправка не повторяется.
Перед заменой работающего окружения сохраните согласованный набор томов app-data,
receiver-data, public-data и прежний образ. Для отката нужны образ и все эти тома.
Не используйте `down -v` и очистку томов.

## Проверка исправлений аудита

Временный контейнер на Tower: 38 интеграционных тестов прошли с
`--import-mode=importlib`; mypy прошёл. Это проверка исходников с зависимостями
существующего образа, а не доказательство чистой пересборки.
Браузерные тесты сохраняют скриншоты в `tmp_path`, не требуют `/artifacts`.
Оба браузерных теста со стандартным Docker seccomp остановились до сценариев:
Chromium сообщил `No usable sandbox`. Полный pytest пока не проходит на этом Tower.
Песочница Chromium остаётся включённой; кастомный seccomp удалён. Для browser e2e
нужно совместимое контейнерное окружение с поддержкой sandbox. Ослабление изоляции
и изменение системных настроек Tower не выполнены.

Приложение и его браузерные сценарии пока используют английский интерфейс.
Согласованные русские спецификация, сценарии, архитектурный контракт и Guardrails
восстановлены из `2e13b3b`; новые требования ими не подменялись.


Интерфейс: разрешения сгруппированы с дочерними делегированиями и результатами.
В Activity доступны поиск по событиям/идентификаторам, фильтры по участнику и типу,
группировка по участнику и сброс. Фильтры меняют только отображение; экспорт полный.

По умолчанию демо раскрывает только текущий шаг: одобрение, делегирование, доставка
и проверка соответствующей квитанции. Полный экран открывается через
`Show full workspace`; выбор сохраняется в рамках сессии вкладки.
Решение о подписанном журнале и внешних контрольных точках без блокчейна:
[ADR-007](docs/ADR-007-SIGNED-HISTORY-AND-EXTERNAL-CHECKPOINTS.md).
Внешнее закрепление истории пока не реализовано.
